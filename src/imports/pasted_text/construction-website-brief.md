# 3. TYPOGRAPHY IS EXTREMELY IMPORTANT

Typography should be one of the defining features of the website.

Do NOT automatically use the most common web fonts or the typical:

Inter
Roboto
Poppins
Montserrat
Open Sans

unless there is a genuinely strong design reason.

Instead, select a sophisticated font combination that feels distinctive, modern and highly readable.

I want typography that makes reading the website enjoyable.

Use a carefully paired type system:

DISPLAY FONT:
A distinctive contemporary grotesk, neo-grotesk, humanist sans, refined serif, or modern editorial display face.

BODY FONT:
A highly readable typeface with excellent spacing, proportions and readability at smaller sizes.

The combination should create contrast without looking fashionable for the sake of being fashionable.

Possible characteristics:

* Slightly unusual but professional
* Excellent letterforms
* Beautiful lowercase characters
* Strong numerals
* Good readability
* Strong punctuation
* Excellent paragraph rhythm

Do NOT choose an obscure font simply because it is unusual.

The priority is:

READABILITY + PERSONALITY + PROFESSIONALISM.

Use the font pairing consistently.

Create a strong typographic hierarchy:

Display
Large headline
Section heading
Subheading
Body
Metadata
Labels
Buttons

Typography should feel intentional at every size.

Use proper:

* Letter spacing
* Line height
* Font weight
* Paragraph width
* Text wrapping
* Optical hierarchy

Avoid excessively wide paragraphs.

Body copy should generally have a comfortable reading width.

Large headlines can be expressive and experimental, but supporting information must remain effortless to read.

Examples:

* Images reveal through clipping masks
* Text moves slightly upward into position
* Large headings reveal line-by-line
* Images subtly shift at different speeds
* Project metadata appears as the project enters view

* Horizontal elements can move subtly
* Sections transition between visual states

Use different motion patterns carefully.

Do not animate every element.

The user should feel:

Motion should create excitement and discovery.

# 25. DEVELOPMENT-FRIENDLY STRUCTURE

The final design will eventually be pulled into VS Code and developed as a real website.

Therefore:

* Keep components logically structured
* Avoid unnecessarily complicated visual effects
* Avoid effects that are impossible or painful to reproduce in React/CSS
* Use realistic web animations
* Keep spacing consistent
* Use a clear design system
* Keep colors tokenized
* Keep typography consistent
* Make content easy to replace
* Make project components reusable
* Make project cards reusable
* Make project detail layouts reusable

The final implementation should be realistic with:

React
CSS / Tailwind
Framer Motion or equivalent animation library
Supabase for project data and image storage

Do not design something that depends on proprietary Figma-only effects.
